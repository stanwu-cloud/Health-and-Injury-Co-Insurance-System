# 傷害及健康保險共保月帳單報表產生系統

讀取共保系統匯出的兩支 CSV，套用既有 Excel 樣板，產出**四種報表**：

| 報表 | 份數 | 資料來源 |
| --- | --- | --- |
| 共保月帳單－T 字帳 | 1 | 保費檔 + 理賠檔（簽單年度 = 設定年的部分） |
| 共保月帳單－彙整表 | 1 | 同上 |
| 當月賠款月帳單－T 字帳 | 每個簽單年度各 1 張 | 只讀理賠檔 |
| **當月共保賠款月帳單－彙總表** | **每個簽單年度各 1 張** | **只讀理賠檔** |

後兩種**共用同一份年度清單**，份數與年度永遠一致；樣本（115 年 5 月）一次執行共 **6 個檔**。

- 執行環境：Windows + JDK 17
- 執行方式為 **CLI 批次**（雙擊 `拜託執行我.bat`）；**GUI（雙擊 `開啟畫面.bat`）自 2026-08-22 起只在 `feature/gui` 分支**，兩者共用同一核心服務層
- 給使用者的操作說明另見專案根目錄之 `系統操作說明.docx`
- 規格文件見 `docs/`；架構與規則以 `..._DESIGN_系統設計.md`、`..._RULE_規則定義.md` 為準

> **⚠ 分支歸屬（2026-08-22）：GUI 只在 `feature/gui` 分支。**
> `dev` 與 `feature/phase-two` 不含 `FxLauncher` / `FxApplication` / `MainController`、`開啟畫面.bat`
> 與 `pom.xml` 之三個 JavaFX 依賴；那兩個分支的 fat jar 主類別是 `entry/CliLauncher`，
> `java -jar target\health-and-injury-co-insurance-system.jar` **直接進批次**
> （`--mode=cli` 保留相容但已無作用，供既有 `.bat` 與排程沿用）。
>
> 報表計算與產出邏輯三個分支**完全同源**，`feature/gui` 只接收 `feature/phase-two` 的合併。
> **共用檔案（`docs/`、本檔、`CLAUDE.md`、`entry/CliRunner`、`entry/CliLauncher`、
> `CoInsuranceApplication`）在各分支必須逐字相同**——分支專屬敘述一旦寫進去，每次合併都會在同一處衝突。
> 真正允許分歧的只有：`pom.xml`、`開啟畫面.bat` 與三個 `Fx*` / `MainController` 類別。

> **第二階段（`feature/phase-two`）已全部實作完成並通過驗收**：P-01 ~ **P-23** 全數結案、T-23 ~ **T-38** 實作完畢、**63 項測試全綠**，**目前無待業務方確認之項目**。爭議與定案內容見 `docs/..._LOG_第二階段問題追蹤清單.md`；**找檔案請先看 `docs/..._GUIDE_文件與資料索引.md`**。

## 快速開始

### 1. 建置

```
build.bat
```

產出 `target\health-and-injury-co-insurance-system.jar`（fat jar）。`dev` / `feature/phase-two` **不含 JavaFX**，約 35 MB；`feature/gui` 含 JavaFX，約 44 MB。
本機無 `mvn`，一律使用專案內的 `mvnw.cmd`。

### 2. 準備資料

```
config/application.xlsx        設定年月（B1/B2）與共保公司清單（A6 起）
templet/PREMIUM_T_ACCOUNT.xlsx T 字帳樣板
templet/PREMIUM_SUMMARY.xlsx   彙整表樣板
templet/CLAIM_T_ACCOUNT.xlsx   賠款 T 字帳樣板
templet/CLAIM_SUMMARY.xlsx     賠款彙總表樣板
input/{YYYMM}/VOLP{YYYMM}.csv  保費匯入檔（可缺，缺檔時只影響前兩張報表）
input/{YYYMM}/VOLC{YYYMM}.csv  理賠匯入檔（可缺，缺檔時賠款以 0 計）
```

`{YYYMM}` 為民國年 + 補零 2 位的月份，例如 115 年 5 月為 `11505`。
兩支 CSV 皆為 **Big5 / CP950** 編碼並含表頭列。

### 3. 執行

```
拜託執行我.bat                        編譯 + CLI 批次，年月取自設定檔
拜託執行我.bat --year=115 --month=5   編譯 + CLI 批次，年月由參數覆寫（優先於設定檔）
```

`拜託執行我.bat`（原 `run.bat`）已內含 `mvnw.cmd clean package -DskipTests`，
雙擊即可完成「編譯 → 執行」；若只想編譯請用 `build.bat`。
`開啟畫面.bat`（開 GUI，不編譯）**只在 `feature/gui` 分支**，連同「不要教使用者雙擊 jar」與 Java 自動探測順序的說明一起。
批次執行不受影響：`拜託執行我.bat` 內含寫死的 `JAVA_EXE`（業務方機器路徑），不依賴 `.jar` 的檔案關聯。

**GUI 執行成功的畫面只顯示兩件事**（R-RUN-05 / D24）：本次使用了哪些匯入檔、成功產出了哪些報表。
金額摘要（共保保費／攤付共保賠款／共保管理費／Balance Due）**不上畫面**，改在主控台與 `logs/report.json` 查；畫面上的數字太容易被當成對帳依據。
**執行中止的畫面則完全不簡化**——失敗要能一眼看出原因。保費檔缺檔時不另跳警語，而是在匯入檔那行看到「未提供：`VOLP11505.csv`」、產出清單裡沒有共保月帳單兩張。

## 放了哪些匯入檔，就會出哪些報表

**兩支匯入檔各管各的**：保費檔決定前兩張報表出不出，理賠檔決定後兩種報表出幾張。少放一支不會讓另一支也停擺。

以下以設定年 115 年 5 月、理賠檔內含 115 / 114 / 113 三個簽單年度為例。**賠款月帳單的 T 字帳與彙總表永遠同進同出**，故每個年度都是「一份 T 字帳 + 一份彙總表」：

| 保費檔 `VOLP11505.csv` | 理賠檔 `VOLC11505.csv` | 共保月帳單（2 張） | 賠款月帳單（T 字帳 + 彙總表） | 總共幾個檔 | 結果 |
| --- | --- | --- | --- | --- | --- |
| ✅ 有 | ✅ 有資料 | **出** | **114、113 各 2 張** | **6** | 成功 |
| ✅ 有 | ❌ 沒放，或只有表頭 | **出**（賠款欄顯示 `-`） | 不出 | 2 | 成功 |
| ❌ 沒放 | ✅ 有資料 | 不出 | **115、114、113 各 2 張** | **6** | 成功，但畫面會警示 |
| ❌ 沒放 | ❌ 沒放 | 不出 | 不出 | 0 | **中止並顯示錯誤** |

### 幾個容易誤會的地方

**Q：為什麼保費檔有放的時候，反而不會出「115 年」的賠款月帳單？**

因為 115 年的賠款已經算在共保月帳單的「攤付共保賠款」欄位裡了，再出一張會重複計算。賠款月帳單只補上「共保月帳單沒算到的年度」。

反過來說，保費檔沒放時共保月帳單不會產出，115 年的賠款就沒人承載，所以此時**會**多出一張 115 年的賠款月帳單。這是刻意設計，不是異常。

> 對帳用的算式：**每一筆賠款一定、而且只會被一張報表算到一次**。
> 樣本驗算：有保費檔時 `126,931（共保月帳單）+ 38,331 + 32,460 = 197,722`；沒保費檔時 `126,931 + 38,331 + 32,460 = 197,722`（全部由賠款月帳單承載）。兩種情況合計都等於理賠檔的全部金額。

**Q：保費檔忘了放會怎樣？會不會安靜地出一張全 0 的報表？**

不會。共保月帳單那兩張**整組不產出**，主控台與 `logs/report.json` 都會標示「保費匯入檔不存在」，並警示保費、管理費、Balance Due 均以 0 計算、非本月實際金額。`report.json` 中的 `premiumFileMissing` 會是 `true`。

**Q：「沒放保費檔」和「保費檔只有表頭沒有資料」一樣嗎？**

不一樣，兩者結果不同：

| | 共保月帳單 | 賠款月帳單（兩種）是否含 115 年 | `premiumFileMissing` |
| --- | --- | --- | --- |
| 沒放檔案 | 不出 | **會** | `true` |
| 檔案在、只有表頭 | **照出**（金額為 0、Balance Due 為負值） | 不會 | `false` |

實務上共保系統無保費的月份是「不匯出保費檔案」，所以只會遇到前者；後者只是程式的防衛性設計。

**Q：理賠檔沒放，和理賠檔有資料但沒有非當年度的簽單，畫面上分得出來嗎？**

分得出來，訊息不同：前者顯示「未產出賠款月帳單：理賠匯入檔不存在」（代表可能漏放檔案），後者顯示「未產出賠款月帳單：無非當年度簽單資料」（代表本月確實沒有）。兩者都算執行成功。

> 規則出處：`..._RULE_規則定義.md` 之 R-EXC-01 / **R-EXC-03** / R-OUT-09、R-CALC-18；爭議與業務方回覆見 `..._LOG_第二階段問題追蹤清單.md` 之 **P-12 / P-13**（含八種輸入組合對照）。

## 幾個容易踩到的地方

程式已針對下列各點實作防護，維護時請勿繞過：

- **CSV 依位置索引取欄，不可依欄名**：兩支檔案各有兩個欄位叫「日額」，理賠檔的「已決賠款 合計」欄名中間還有半形空白。欄位定義集中在 `constant/PremiumColumn`、`ClaimColumn`，並於讀檔時驗證表頭。
- **攤付共保賠款須先篩「簽單年度 = 設定年」**（只篩年、不篩月）。漏篩會由正確的 126,931 變成 197,722。
- **中央再保（`N19`）採差額法**：分攤金額 = 總額 − 其餘公司加總，用來吸收其餘公司四捨五入的尾差，**不是**總額 × 7%。判定依公司代號，不依列號——設定檔中 N19 位於第 14 列，而彙整表樣板中卻位於最末列（A22）。
- **設定檔成分合計必須等於 100%**，不符即中止，不產出任何檔案。
- **捨入一律 HALF_UP**，且只能經 `calculator/RoundingUtil`。`BigDecimal` 預設是 HALF_EVEN，誤用會產生 ±1 元帳差；`StaticGuardTest` 會掃描原始碼把關。
- **共保管理費的捨入順序不可調換**：逐家分攤保費四捨五入 → ×6% → 再四捨五入 → 最後加總。先加總再乘會得到 21,007 而非正確的 21,009。
- **彙整表 A 欄不覆寫**，列順序以樣板為準，程式用公司名稱回查設定檔取得代號與成分；查無對應即中止。
- **彙整表 F 欄（應分配保費）為負值、G 欄（應攤配賠款）為正值**，D 欄為 `=B{n}-C{n}`。這組符號慣例於 2026-08-10 調整過，改公式前請先看 `..._MAPPING_欄位對照.md` §8.2。
- **不要拿 `產出範例/` 當驗收基準**。那些範例已於 2026-08-18 全面以實跑輸出取代（R-06 / T-22 / T-29 / T-38），金額現在是對的——但**範例是程式的產物，不是事實來源**，拿它當基準等於用程式驗證程式自己。驗收數值一律以文件所載為準，`StaticGuardTest` 會檢查測試碼未引用 5% 版舊值。

第二階段（賠款 T 字帳）另有四點：

- **`CLAIM_T_ACCOUNT.xlsx` 與 `PREMIUM_T_ACCOUNT.xlsx` 只差 A2 標題，但不可共用 `TAccountCell`**。五處語意不同：`P4` 年份來源是**簽單年度**而非設定年、`G20` 留空、Balance Due 改寫 `G21`、`O20` 也要寫。故另立 `ClaimTAccountCell`（R-OUT-08）。
- **Balance Due 直接等於該簽單年度的賠款總和（正值）**，不是「共保保費 − 賠款 − 管理費」。誤套第一階段的 M8 會得到符號相反的 −38,331。
- **`M10` 的「排除設定年」是有條件的**：保費檔存在才排除。寫成無條件排除的症狀是 115 年的 126,931 憑空消失且帳面上看不出來——`verifyConsistency()` 的「賠款承載完整性」在執行期把關（R-CALC-18 / D19）。
- **備份清單與寫出清單必須由同一個 `premiumFileExists` 旗標控制**：`BackupService` 用 `Files.move()` 搬檔，備份了卻不重寫會把前次成果移走且不補回。另外「全部落空」的中止點必須在一致性檢查之後、**備份之前**，否則會留下有備份無產出的空目錄（D16 / D17）。

第四張報表（賠款彙總表）再加三點：

- **⚠️ `G` 欄（應攤配賠款）的分攤基準是「該年度合計」`C23`，不是各公司自己的賠款**。誤用的話——`C23` / `G23` / `J23` **三個合計仍然全對**，因為中央再保的差額法會把差異全數吸收；只有 `G` 欄逐家金額會露餡（15 家歸零）。所以**測試必須逐家斷言 16 列**，`J23 == 0` 那條零和檢查擋不住它（TASK K20）。
- **`B` 欄餵 0 就好，不必為本報表另寫公式**：`F` / `I` 與中央再保差額法三組公式都以 `$B$23` 為輸入，`B` 欄全 0 時它們自動歸 0。公式邏輯放在 `writer/SummarySheetPainter`，**與第一階段彙整表共用**——改它等於同時改兩張報表。
- **年度一律取簽單年度**（`A3` 的 U/Y、`C` 欄、檔名），**只有 `E3` 資料統計年月取設定檔年月**。`A3` 若誤取設定年，同一批報表裡 114 年的彙總表會寫 2026、T 字帳寫 2025，兩者打架。

## 開發

```
mvnw.cmd test                     執行全部測試（63 項）
mvnw.cmd -o test                  同上，離線模式（相依已在本機倉庫）
mvnw.cmd clean package            建置 fat jar（含測試）
mvnw.cmd clean package -DskipTests
```

兩支 `.bat` 取得 Java 的方式不同：

| 檔案 | 取得方式 | 換機器時 |
| --- | --- | --- |
| `build.bat` | 內建 `JAVA_HOME`＝`C:\Program Files\Amazon Corretto\jdk17.0.18_9`（開發機） | 需改檔 |
| `拜託執行我.bat` | 內建 `JAVA_EXE`＝`C:\Users\user\.jdks\corretto-17.0.18\bin\java.exe`（**業務方機器**） | 需改檔；在開發機上會停在「找不到 Java」，屬預期行為 |

`拜託執行我.bat` 是寫死路徑；自動探測邏輯在 `開啟畫面.bat`（僅 `feature/gui`）。
兩支 `.bat` 皆以 `pushd "%~dp0"` 開頭、於**每個結束點** `popd`，因此自任何目錄呼叫都能正確解析 `config/` `input/` `output/` 等相對路徑，且不會污染呼叫端的當前目錄。
`.bat` 一律為 **UTF-8 無 BOM + CRLF**（檔內以 `chcp 65001` 切碼頁）；存成 LF 或加上 BOM，cmd 會報出與實際無關的錯誤訊息。

第二階段一律在 `feature/phase-two` 開發，驗收後才合回 `dev`。
